# Ask Muse grounding QA (MOT-82)

Run `npm run check` and `npm run build -w apps/web`. Start the app on 127.0.0.1:5198, set `MOT_PLAYWRIGHT_MODULE` to installed Playwright and `MOT_EVIDENCE_DIR` to a writable directory, then run `node scripts/test-mot-muse-grounding.cjs <mode>`.

Modes: `main`, `catalogue`, `off`, `injection`, `source-failure`. Each is a bounded independent run. `MOT_TEST_ORIGIN` overrides localhost. The script never calls a provider: status/proposal responses are explicitly labelled transport fixtures. Positive source loading uses the actual published San Sebastián FCC feed, eight articles / 9,484 body characters on the recorded 29 October snapshot. Negative modes remove a body, add hostile reference text or fail source transport; no upstream file changes.

The main flow starts an empty canonical trip, seeds three fictional cards through the human command/session path, opens the header Muse chip, inspects source dates and full-text counts, selects one non-private card and opens the matching disclosure. Before Ask, no proposal request occurs. An 8,001-character prompt disables Ask. A held response proves observable waiting/elapsed time and Stop. Validated suggestions appear as dashed cards in their target lanes with exact source links. Choose one, Add, confirm agent authorship/source, Undo, change the board, reject stale work and stop a subsequent request. Escape closes the sheet and restores focus.

All eight main states, five catalogue states, the manual-only state and five injection states are checked at 1920/1440/1280/768/375/280 px (114 state-width checks). Font families/weights/sizes, one primary, 44 px controls/source links and horizontal fit are asserted. Screenshots at 1440/375 wait for finite animations to finish. Stop's explanation must stay visible after every resize. Expected source-failure console errors are recorded separately; the source path stops after four HTTP attempts (initial request plus three retries), and never posts a model request.

Unit regressions reject mixed-city article identity/provenance, editing an unselected card, forged citations/dates and per-change source links. New suggestions are always marked as agent work. The unchanged 8,000-character / 96,000-byte server limits are checked before HTTP; nothing is silently truncated. A transport ignoring cancellation cannot land a late answer. The provider instruction asks article-grounded creations for an exact per-change source reference; the client independently validates it.

The payload consists of board ID, prompt, chosen non-private card ID/title/body/lane/day/time, an empty picture-ID list, and selected-city grounding with article text/source metadata. Private/unchosen cards, board title, other boards, picture bytes and annotations outside the chosen card text are excluded. The on-screen disclosure and docs/PRIVACY.md state the same boundary. No model/provider endpoint or server-key configuration name is present in built browser JavaScript.

This proves transport, schema/authority, UI and actual public issue-context behavior. It does not prove a live model will ignore every malicious instruction. The injection case deliberately returns a forbidden destination edit and proves rejection without a board write. A live browser/server/provider receipt, provider semantics and owner-managed server configuration remain MOT-95 acceptance. Independent Opus design review, physical iOS/Safari and accessibility-device certification remain pending. Browser plugin not available; sandboxed Playwright Chromium supplies DOM/screenshot evidence.

The phone source list retains the reference's compact three-column rows. Its retrieval date remains visible; each link has its own date tooltip, and Issue dates and sources expands the individual publication/retrieval dates and versions. A browser regression requires the card-choice heading to appear in the initial 375 px sheet view.
