# Muse runtime QA (MOT-95)

Run `npm run check` and `npm run build -w apps/web`. Start the local app on 127.0.0.1:5198. Set `MOT_PLAYWRIGHT_MODULE` to installed Playwright and `MOT_EVIDENCE_DIR` to a writable directory. Run `node scripts/test-mot-muse-runtime.cjs <mode>` separately for `off`, `checking`, `oversize`, `stopped`, `timeout`, `limit`, `provider`, `invalid` and `test`. `MOT_TEST_ORIGIN` overrides localhost. All status/proposal responses are explicitly labelled transport fixtures; no model, credential or paid request is involved.

The flow is: empty canonical San Sebastián trip → header Ask Muse → reported runtime state → deliberate request or disabled Ask → unchanged board on failure/Stop → safe diagnostic copy or approved fixture creation. Public FCC issue loading uses the actual selected-city feed. Runtime states are checked at 1920/1440/1280/768/375/280 px for horizontal fit, Plex type/weights, at least 44 px targets and at most one primary. Screenshots are retained at desktop and phone widths. The test-creation case applies one proposal, persists and reloads, then verifies both durable test origin and visible Test adapter attribution. It does not claim Muse generated anything.

The error modes include private canaries in the fake provider error message, proxy HTML and arbitrary receipt fields. None may appear in the screen or copied diagnostic. Clipboard JSON must match the rendered safe receipt (Windows clipboard line endings may differ). The receipt contains operation, board ID, revision, error class and timing, never request/card text. Off/checking/oversize make zero proposal POSTs. Other fixture failures make one and leave zero cards/ghosts. Limit state exposes Plan by hand rather than a committing retry. Stop suppresses late answers.

Re-run `node scripts/test-mot-muse-grounding.cjs main` for the existing selection/disclosure, source citation, observed work, partial Add/Undo, stale board, Stop, Escape and focus checks. `off` additionally verifies an actual manual board edit with no provider request. Browser plugin not available; use sandboxed Playwright Chromium. Physical iOS/Safari and assistive-device results are not inferred from Chromium.

Unit regressions in `packages/mot-server/src/settlement.test.ts` exercise the unchanged 30-second deadline using fake timers and transport that ignores AbortSignal. A cancelled/timed-out job must settle promptly, retain a single active-call lease while transport remains pending, and emit no late success log. Existing server runtime/HTTP tests retain origin/header/body/rate boundaries. `muse-runtime.test.ts` checks typed client errors, no-send limits and receipt projection; test-attribution tests verify durable context and Undo. Existing limits, schemas, thresholds and harness configuration remain unchanged.

MOT-95 remains Doing until owner-managed server configuration, a real browser → server → provider → validated proposal receipt at a recorded application revision, production boundary controls where applicable, and independent design review. Fixture evidence does not satisfy live acceptance A14. No deployment, credential handling or paid call is authorized by this QA document.
