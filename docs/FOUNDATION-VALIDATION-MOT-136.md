## Gate zero: reliability, privacy and truthful state

Every applicable declared correctness/negative fixture must pass before an approach can be supported for release. Any lost acknowledged authored content, unauthorized disclosure/action, wrong-trip write, unexplained stale media, fabricated save/retention receipt or silent selection loss blocks acceptance regardless of visual preference.

Record the exact defect and affected scope. Stop a study path that exposes unsafe behavior; preserve the result as a failure, and distinguish unperformed later steps. Do not interpret a shared-engine defect as evidence that a different default entry solves it. Pending room/device/HTML/external-environment coverage remains pending; it cannot pass through a conditional skip.

## T1: comparable first use and collection

**Proposed sample:** six consenting adults unfamiliar with this build. Seek a mix of people familiar/unfamiliar with using their own Muse; record actual experience and limitations. These are small qualitative diagnostic sessions, not population inference. Participant recruitment and any new prototypes are outside MOT-136's execution authority. An owner-only walkthrough can find defects but cannot fill six participant records or establish comparative preference.

Compare A and B in the same supported environment with matched inputs. Three participants use A then B; three use B then A. Alternate destination fixtures independently of that order. Record deviations; do not pool incomparable runs as if matched. Preserve manual fallback in both variants; identify what the participant actually used.

Each participant starts from a fresh trip and, without UI coaching:

1. Identifies the destination and useful next action.
2. Adds an unlisted place with an address/map reference and a personal photo/note.
3. Assigns an activity to a day using supported controls.
4. Changes a choice, uses Undo, and correctly explains where their latest work is saved.

Moderator may read the same neutral task wording and clarify the scenario. Pointing to a control, completing a step, editing a file or supplying a rescue prompt counts as assistance. Record assisted and unassisted outcomes separately. Allow supported assistive technology; document access needs and any unmatched conditions.

**Proposed operational measures:** first purposeful action within 60 seconds; all four task groups completed within eight minutes; wrong turns, repair steps, assistance, data/control misunderstandings and the participant's explanation/preference. These are study cutoffs, not an app-speed budget or a claim that holiday enjoyment should be rushed.

A purposeful action advances the requested trip task; merely opening a menu does not qualify. A wrong turn requires backtracking from an action that did not advance it. A repair is extra work to correct an error or recover state. Normal supported handoff steps are recorded as effort, not mislabeled errors. Record first-action and completion outcomes separately. T2/T4 comprehension thresholds apply to each candidate being recommended, not a pooled score across variants.

After both variants, ask which they would choose for another trip and why. A preference counts toward the decision rule only when grounded in the tested job/control/effort rather than appearance alone. Preserve raw answers and the moderator's coding explanation; a reviewer can dispute the classification. Give the actual participant count and each paired result, not just an average.

## T2: predict inclusion and preserve a personal collection

Using a populated fixture, ask what will appear in Memories, selected composition/output and the chosen postcard. Compare the person's prediction with the predeclared per-view policy, source snapshot, selection/exclusion reasons and actual visible result.

Exercise media replacement, caption edit/clear, view changes, rapid navigation, Undo/Redo, acknowledged save and cold native restore. Overlap completions deliberately in the engineering fixture. A private item, unknown location or excluded hotel must have the declared scoped behavior; invisibility is not automatically data loss.

Record whether at least five of six participants can correctly explain inclusion and the latest save state without coaching. Independently, every applicable content/privacy assertion must pass; a participant comprehension rate cannot excuse a correctness failure.

## T3: supported own-Muse path

MOT-128/129 exercises a real authorized external environment: discover public guidance, select permitted current context, return a supported versioned proposal/file, inspect intended changes, approve/apply, observe the actual save receipt, then Undo. Include stale/conflicting input and permission boundaries. No hosted key is required for the supported file route.

Unavailable external tooling, missing guide capability or manual technical rescue makes that part unvalidated. Do not replace the actual external run with an emulator or silently count manual fallback as an agent success. B is not a fair comparator when its intended path is unavailable. Do not interpret a disabled hosted adapter as proof that the native external-Muse path failed.

## T4: publication as the actual trip

Before output, obtain the participant's predicted selection/order and identify brief, day plan, personal material, editorial sources and intentional apparel. Compare actual preview, moved offline HTML and cold native restore with the independent expected inventory and approved manifest. Check visible media versions/captions, full intended text/continuations, complete venue identity, credit and private canaries.

No new PDF generation/testing. No invented image rights, route stops, visits, bookings, purchases or historical denominators. An output receipt/hash is necessary evidence identity, not proof of visible fidelity. Missing output capability stays pending.

At least five of six participants should identify the trip framing and correctly predict selected/excluded material without coaching. Every applicable fidelity/privacy assertion must also pass.

## T5: host/shared, offline and devices

MOT-129 retains actual host-master/guest-copy and two-household/device flows, concurrent edits/votes, offline reconnect, revocation and private-scope checks under the approved method/trust/geometry contracts. Native package possession does not confer a room role or permission to publish. MOT-100 retains real iPhone/iPad Safari receipts; desktop responsive screenshots do not replace them.

These production gates are independent of T1's comparative study. Preserve existing 2 s cached/4 s first-load app budgets and their real profiles. No new harness edit, timeout relaxation or acceptance exception is authorized here.

## Predeclared decision rules

The owner approves these rules before observation. They determine the recommendation presented for a later owner decision; they do not automatically change the live app.

Apply the rows in order: correctness failure, missing prerequisites, B-backup recommendation, A-retention, then inconclusive/revise. Preference is one first-choice answer per participant; ties/undecided answers count for neither candidate.

| Condition | Recorded outcome and next action |
|---|---|
| Any gate-zero failure | Hold acceptance/release for that defect. Repair and rerun the affected checks. Preference or visual quality cannot override it. |
| Missing owner-approved protocol, matched variants, required fixture/version bindings, real comparator capability or authorized participants | Validation pending/inconclusive. Do not claim A or B won. Owner's current A selection remains a product decision, not a validated preference. |
| B meets the same 5/6 first-action, completion and T2/T4 thresholds and has no fewer T1 completions than A; at least 4/6 participants prefer B for a qualified job/control/effort reason AND at least 4/6 paired runs need fewer wrong turns/repair steps in B; all applicable correctness gates pass | Recommend the B backup to the owner. Preserve the same full trip, manual route and publication capability. Do not switch the live default without the later owner decision. |
| A has at least 5/6 unassisted first purposeful actions within 60 seconds and 5/6 T1 completions within eight minutes, T2/T4 comprehension each at least 5/6, at least 4/6 participants prefer A for a qualified job/control/effort reason, all applicable correctness gates pass, and the backup rule is not met | Retain A as the supported direction for this tested cohort/build. Report uncertainty; no population/product-market-fit claim. |
| Neither direction meets its rule, or preference/repair evidence conflicts | Revise the first useful state or hypothesis and repeat under a new protocol/build binding. Do not rescue the hypothesis with a post-hoc score or silently lower a threshold. |

Participant attrition, prior exposure, access differences, protocol deviations and missing environments stay visible in the denominator. Six is the proposed completed paired sample; fewer records are incomplete evidence for these cutoffs. Revisions occur prospectively, not by rewriting an observed result into a pass.

Each T1–T5 receipt records run ID/date, protocol/source/fixture/expected-inventory identity, operator and actual participant/reviewer roles, environment and order, task outcomes/timing, assistance/wrong turns/repairs, exact visible state, failures/exclusions, private evidence locations and the resulting disposition. Record explicit pending evidence instead of invented names, customer votes or designer participation.
