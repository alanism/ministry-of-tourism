# Photo illustrations: Fashion Illustration and City Ink

On the board, choose **Create photo illustration**. Choose **Fashion Illustration · people** or **City Ink · streets and architecture** in Illustration treatment. This opens a photo-specific Muse Image flow without enabling the older optional city/venue feature flag. Board editing still works without a key. The older city/venue text-to-image flow remains available and uses its existing generation endpoint.

Choose a photo you have permission to use. Selecting it does not upload anything. MoT accepts one PNG, JPEG or simple static WebP within the existing 10 MiB/16-megapixel image bounds. It validates the header before decoding, redraws a copy as a JPEG with a maximum 1,600-pixel longest side, removes original file metadata by re-encoding and shows that prepared copy. The original file is neither changed nor saved to the board. Files and requests are not chosen from private board cards automatically.

In **Use my own key** mode, the user enters their own Meta key into this panel's memory and explicitly agrees to send the selected prepared photo for a paid generation. **Generate fashion illustration** sends that prepared copy as IMAGE 1, the approved fashion reference as IMAGE 2, the fixed style prompt, one portrait image request and the session key directly to `https://api.meta.ai/v1/images/edits`, model `muse-image-1.0`. No MoT server receives the photo or key. This explicit BYOK path never uses the funded proxy or a saved credential. Closing or switching panels drops the panel key and source image. The key is absent from request bodies, boards, exports, browser storage and diagnostics. All image-search, web-search and shell tools are disabled for this edit. No other board data, photos, notes, bookings, city or filenames are attached. The selected approved style reference is the only additional image, and the consent text states this explicitly.

The versioned prompt in `muse-fashion-preset.ts` adapts the owner's approved 4 November fashion test: fine ink contours, flat restrained colour, soft shading, preservation of the visible face/pose/clothing/crop, and a plain white background. Following the owner's 5 November direction, it includes the original approved fashion style reference, unchanged, as IMAGE 2. IMAGE 1 supplies the person, clothing, pose and crop; IMAGE 2 supplies only drawing style. This unreleased version 1 was finalized before its first deployment. Provider fixtures verify input order and bytes; live fidelity with arbitrary traveler photos still needs an approved paid check. Likeness and fine artwork may be redrawn. Output is opaque, not a transparent cutout; no background-removal step is implemented or implied.

City Ink uses a second versioned prompt in the same file, adapted from the actual saved FCC production prompt and the two approved city-photo edit tests recorded in `Muse-Image-Test-Prompts-2026-11-04.md`. It uses the chosen photo's buildings, viewpoint and framing, fine near-black architectural lines, white paper and a central blue `#1f64aa` band. It requests the source's prepared aspect ratio. Unlike the earlier test prompts, it asks the model to generate no lettering. `city-ink-label.ts` adds the exact mixed-case **MoT** locally in white IBM Plex Serif on a small blue backplate near the upper center; those modified image bytes are what the user reviews, downloads and saves. The mark's placement is fixed, not detected from the generated band, and may cover some linework. Architecture, layout and framing still require review. The original approved FCC City Ink reference is bundled unchanged and sent as IMAGE 2. The prompt prevents copying its street geography or FCC lettering; the selected photo is IMAGE 1. The local label and two-image request have fixture/browser coverage; no new live generation was performed.

Meta's [image API documentation](https://dev.meta.ai/docs/image-generation) documents the raw JSON `images: [{image_url: "data:image/...;base64,..."}]` edit request and opaque output. An unauthenticated CORS preflight against `/v1/images/edits` returned HTTP 200 with `Access-Control-Allow-Origin: *`, allowed request headers `*` and POST allowed during this implementation. This checks browser transport compatibility without sending a key, photo or paid request. Actual production browser generation remains untested here. The UI links current pricing, explains that Meta's own terms apply and that cancellation/timeouts may already have incurred a charge.

The generated image is shown for review with AI attribution. Nothing is added before review. **Save private illustration for magazine** uses the normal command boundary to register the generated asset and create one private photo card in Remember in a single validated command run. It retains the model, correct fashion/City Ink preset/version and creation time. City Ink's saved card also records that MoT lettering was added locally. The source photo is not registered or silently bundled with the result. Existing cards and original photos remain unchanged. Agents cannot read the private output. The user may download or discard a preview; deleting a preview does not delete an already saved card.

To use the saved illustration, open **Keepsakes → Magazine** and explicitly select **Include private notes and artwork in this preview**. The private result is excluded from the default shared/public magazine and exports. In Export, choosing **Review copy** includes private content as a separate explicit choice. Tests cover both treatments' private exclusion, personal-magazine inclusion with a rendered page and retained AI credit. Browser checks cover review, save, reload and a private HTML magazine export without the key or original filename.

The free preview sends one image request per click, without judging, retries or BYOK fallback. Explicit BYOK mode retains single-image generation and the optional approved quality loop below. Both modes use one generation at a time, a four-minute request timeout, 4 MiB maximum prepared source and 16 MiB returned-image limit. Stop and panel close abort the request and ignore late output; they cannot guarantee that Meta stops billing. Source preparation and saving also abort on close. Results for another board cannot be added.

No real key was accessed, stored or configured for this implementation. All generation tests intercepted provider requests and used fictional credentials and previously approved output as a fixture. No paid photo generation/scoring request, commit or push was performed. The earlier direct-to-Meta photo UI was deployed with the owner-approved 5 November Firebase release. The new funded UI, storage wording and local magazine recovery described below are source changes and have not been deployed or verified with a paid live request. The static deployment can serve this direct-to-Meta BYOK UI; it is now published in the approved Firebase release. Public discovery has a separate deployed, attested Firebase backend described in `public-discovery-backend.md`; the legacy loopback server is also retained.

## Funded hackathon preview (local source; not deployed)

The panel defaults to **Free hackathon preview**. It checks `/api/muse/images/status` without initializing Firebase or uploading a photo. Readiness means configuration is present, not a promise of remaining quota. Missing, invalid, expired or disabled configuration keeps Generate disabled and offers an explicit own-key choice. No provider key is sent to the browser.

After selecting a photo and accepting separate free-preview consent, the client reads nonsecret `/discovery-public.json` and Firebase initialization metadata, then lazily loads the same persistent anonymous Auth identity and App Check runtime used by public discovery. Each request uses a fresh limited-use App Check token. It sends only `{requestId, style, photoBase64, consent:true}` to the fixed allowlisted Gen2 image function at `https://us-central1-nonhumanintelligence.cloudfunctions.net/motFundedImages/api/muse/images/edit`, omitting cookies and referrer. The direct URL avoids Hosting's 60-second rewrite timeout for potentially four-minute image work. Status stays same-origin. No server-returned URL, client prompt, reference override, model, filename or board data is accepted. The server supplies and checks the approved reference and fixed style; see `funded-images.md` for admission, privacy and deployment controls.

The displayed allowance is at most **2 image attempts per anonymous guest identity for its lifetime, 20 shared attempts per UTC day, 100 shared lifetime attempts and 1 concurrent request**. These are server-enforced ceilings, not per-person guarantees; deleting browser identity does not reset global limits. Failures, Stop and uncertain results may consume an admitted attempt. No automatic retry, quality review or fallback to a personal key happens in free mode. The browser validates the single PNG response, metadata, dimensions, byte and pixel limits before review. City Ink receives the same local exact MoT lettering step before review/download/save. Changing funding mode resets consent; returning to free mode clears the ephemeral own key and quality toggle. Closing the panel clears both modes' source/key/candidates.

Tests intercept every external request with fictional Auth/App Check/Meta responses; they do not prove live reCAPTCHA, IAM, CORS, provider fidelity or billing. A separate owner-approved paid smoke test and deployment are still needed. Do not advertise the free offer as live until those checks pass.

## Storage feedback and downloaded-image recovery

A generated result says **Saved privately for magazine** only after its image write succeeds and the existing OpenTrip `whenSaved` board-write fence resolves. FreeBoard passes that callback through MuseImagePanel to the photo flow and to local image recovery. While the board write is pending, Save stays busy and cannot add a second card. A rejected or missing fence, or tab-only image storage, says **Added privately · this tab only**, explicitly states that saving on this device was not confirmed, and asks the traveler to download the illustration and a full editable ZIP before closing. The already-applied card and bytes remain recoverable without another commit or paid generation. Closing aborts the confirmation wait and ignores a late result. A confirmed device save is not a cloud backup or a promise against later browser eviction.

For an image already imported with **Add images**, select the board image, open **Arrange selected item → Open / edit**, review it and choose **Use image in magazine**. This reuses the exact existing local asset as a private photo card in Remember. It makes no AI call, preserves the original board placement/bytes/credit and existing provenance, and does not invent AI attribution for arbitrary uploads. It refuses missing, changed or already-used selections; Undo removes the added card while leaving the board image. Private magazine preview and Review copy export still require explicit choices and default off/public after reload. No private-preview preference is persisted silently.

## Approved reference files

The owner-approved originals are served at `/assets/photo-illustration/fashion-reference.png` and `/assets/photo-illustration/city-ink-reference.png`. `photo-style-reference.ts` pins their SHA-256 hashes and loads the selected file without credentials before any paid request. Missing, replaced or corrupt reference bytes stop generation before Meta receives a photo or key. The panel shows the chosen reference and exact prompt in its style disclosure. Only the resulting illustration is saved; neither the selected source photo nor the reference is silently registered as a board asset.

## Approved quality review and bounded retries

In explicit **Use my own key** mode, the traveler can opt into **Score and improve with the approved rubric** before consenting to a paid run. This control is disabled in the funded free preview; its allowance does not pay for judging or automatic revisions. The exact owner-supplied 18,510-byte Markdown is preserved at `apps/web/src/trip/image-quality-rubrics.md` (SHA-256 `d2b8ac6db401bc911599d473d68917543471de9481da20fb8be6972ebca45e09`). The app selects the relevant Fashion or City section with the shared instructions, without rewriting any of the 20 criteria or five anchors. The full selected rubric is available in the panel.

After each received image (after the local MoT lettering for City Ink), a separate direct BYOK request sends the prepared source, exact approved reference and full-resolution candidate to `https://api.meta.ai/v1/chat/completions`, model `muse-spark-1.3` **Standard**, no tools, `store: false`. This never uses Contributor or the public discovery service. The browser sends no board content, original filenames or other photos. The consent explains up to three image charges plus three token-priced reviews and several minutes of latency. Closing the panel drops the session key and all transient candidates/scorecards.

Every candidate receives all 20 integer scores (1–5), visible evidence and required corrections, every critical/shared gate (pass/fail/unverified with evidence), up to three main defects and successful features to preserve. Missing or malformed scorecards are unavailable, never a pass. The app recomputes the total and accepts only **80/100 or more plus every critical/delivery gate passed**. There is no 90-point target or minimum per-row score. The local PNG/header delivery check cannot prove artistic fidelity. Model estimates do not guarantee likeness, architecture, alpha or style. Opaque white is the requested background; no cutout is claimed. The UI provides a full-resolution link for traveler inspection at 100%; provider vision may resample supplied images, so automated fine-detail judgments remain estimates.

One initial generation plus at most two revisions is permitted. Critical failures and then the three lowest scoring rows drive revision instructions, preserving successful features and the original photo/reference. Each revision is regenerated from those same two originals and fully rescored. Gate-passing candidates rank ahead of gate-failing candidates, then by total. All received candidates remain selectable; the best is selected for review. Reaching the cap is explicitly target-not-met, never success. Failed/uncertain generation, unavailable judging, Stop or Close prevent further automatic requests. A late result is ignored; already received images remain reviewable when stopping. Starting another run is an explicit new charge decision. Nothing is saved automatically, even when the target is met. The existing private save and magazine/export choices remain authoritative; scorecards and source images are not attached to the board.

Local tests use strict mocked scorecards and approved prior images. No paid quality-judge or regeneration call has run, so actual provider schema support, calibration, costs and output improvements still require a separately approved live smoke test. API shapes follow Meta's [image understanding](https://dev.meta.ai/docs/image-understanding), [structured output](https://dev.meta.ai/docs/structured-output) and [Standard model selection](https://dev.meta.ai/docs/models) documentation.

An unauthenticated OPTIONS preflight for the Standard vision endpoint on 5 November returned HTTP 200 with `Access-Control-Allow-Origin: *`, headers `*` and POST permitted. No key, photo, generated image or paid request was sent. This verifies browser CORS compatibility, not successful authenticated scoring.
